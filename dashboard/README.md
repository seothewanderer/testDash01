# 드론 진로 탐색 테스트 대시보드 · 시각화 개선판

첨부 설계서와 기획안의 **산업 이해 → 직무 탐색 → 준비 역량 → 수집 채용 공고 → 준비 로드맵**을 검토하는 로컬 대시보드입니다. 전체 CSV 54개를 확인했지만, 핵심 질문과 연결에 필요한 17개만 본 화면에 사용합니다.

예시 HTML의 시각적 탐색 방식을 참고해 차트와 선택 동작을 화면 앞에 배치했습니다. 근거 설명과 검토 의견은 각 모듈의 더보기에 유지했습니다.

| 단계 | 주요 시각화와 연결 |
| --- | --- |
| 산업 이해 | 3개 연도별 추이, 활용 분야·연구 기술 막대 → 분야/기술 선택 |
| 직무 탐색 | 직무 분류 타일 → 후보 선택 → 사전 역량 비교 행렬 |
| 준비 역량 | 보유 기술 표시, 교육시간·회차 산점도, 월별 개설 분포 → 과정 선택 |
| 수집 채용 공고 | 지역 타일, 경력·학력 구성, 직무 분포, 방산 근거→채용 직무 흐름도 |
| 준비 로드맵 | 선택한 직무·역량·교육·공고·행동의 5단계 경로와 조건 비교 |

지역 타일은 위치를 단순화한 도식입니다. 직무 타일 면적은 수량을 나타내지 않으며 실제 개수를 별도로 표시합니다. 방산 흐름도의 선 굵기는 필터를 통과한 고유 공고 수입니다. 기업 미연결·미분류를 별도 집단으로 보존합니다. 전체 키워드 빈도를 직무별 수요로 바꾸거나 방산 기업을 임의의 이분법으로 나누는 계산은 적용하지 않았습니다.

## 바로 보기와 공유

`dist/index.html`을 최신 Chrome 또는 Edge에서 열면 됩니다. 서버·인터넷·Python 설치 없이 HTML 파일 하나로 데이터 탐색과 검토가 가능합니다. 외부 원문 링크를 여는 경우에만 인터넷이 필요합니다.

1. 산업·국방 활용 사례를 살펴봅니다.
2. 직무 탐색에서 관심 활동으로 후보를 좁히고 직무를 선택합니다.
3. 준비 역량에서 보유 기술을 체크하고 교육·프로젝트 후보를 선택합니다.
4. 수집 공고에서 지역·경력·기업 근거와 조건을 확인하고 비교 대상을 선택합니다.
5. 준비 로드맵에서 내 조건과 공고를 비교하고 다음 행동을 정합니다.

각 모듈의 **더보기**에는 사용 데이터, 설계 근거, 연결 흐름, 활용 목적, 기대효과, 계산 규칙, 한계와 검토 입력란이 있습니다. 원본 파일 버튼은 검색·페이지 이동·결측 정보를 갖춘 데이터 열람창을 엽니다.

검토 판단은 **미검토 / 유지 / 수정 / 제외**입니다. 제외는 의견으로 기록되며 화면에서 바로 삭제하지 않습니다. 제작자 검토 화면에서 의견을 모아 볼 수 있습니다.

**검토 내용 포함 HTML 저장**을 누르면 현재 직무·과정·공고·개인 입력·기술 체크·검토 메모가 들어 있는 별도 HTML을 내려받습니다. 이 파일을 팀원에게 전달하면 동일한 상태에서 검토를 이어갈 수 있습니다. 검토 의견만 JSON으로 저장할 수도 있습니다. 자동 저장이나 공동 편집 서버는 없으므로 창을 닫기 전에 저장해 주세요.

## 데이터가 없는 부분

현재 모집 상태, 직무별 실제 요구 기술 빈도, 교육 커리큘럼, 현직자 업무 사례, 방산 공고의 특수 지원 조건, 교육·자격 이후 성과, 실제 경력 이동의 7개 영역은 결과를 비워 놓았습니다. 각 영역은 필요한 필드, 기존 데이터와 연결할 키, 활용 방식, 목적·기대효과, 수집 경로를 설명합니다. 가상 수치나 모의 그래프는 없습니다.

특히 공고별 기술 관계표, 커리큘럼, 최신 모집 상태를 우선 보완 대상으로 제안합니다. 현재 자료의 빈도표만으로 공고별 관계를 복원하지 않습니다.

## 데이터 해석 범위

- 기준일은 설계서와 동일한 **2026-09-26**입니다. 교육 일정 상태는 이 날짜 기준이며 모집 상태가 아닙니다.
- 기업–공고는 정확한 이름 일치 52/135개만 연결합니다. 미연결 83개 공고는 유지합니다.
- 직무–공고 분류, 직무–과정은 공개된 문자열 규칙으로 만든 **검토용 후보**입니다. 의미 기반으로 검증된 추천이 아니므로 추천 이유와 원문을 검토해야 합니다.
- 관심 직무와 지역은 해당 데이터에 연결 가능한 범위에서 적용합니다. 산업 전체 수치·키워드 전체 빈도에는 개인 필터가 적용되지 않습니다. 활용 분야는 개별 공고의 사업 성격으로 추정하지 않습니다.
- 직무 변경 시 이전 과정·공고·프로젝트·완료 체크를 비웁니다. 보유 기술과 검토 메모는 유지합니다.
- 연봉 명시 9개 공고만 원문에서 다시 읽습니다. 알려진 범위 오류 2건을 파생값에서 수정하고 원본은 보존합니다. 불명 금액은 연봉으로 환산하지 않습니다.
- 교육 비용 147/148개는 산술관계가 불일치합니다. 원본 네 필드를 병렬로 표시하고 개인별 자비부담을 확정하지 않습니다.
- 방산 관계는 근거 종류·강도·시점을 함께 표시합니다. 공식 지정 미검증은 지정 아님이 아니며, 미분류는 민간 확정이 아닙니다.
- 과제·계약은 업무 맥락 자료입니다. 채용 인원·취업 가능성·합격률로 바꾸지 않습니다. 연구는 기존 고신뢰 분류를 기본으로 쓰며 분류 자체의 타당성을 외부 재검증하지 않았습니다.
- 산업·연구·공공 활용·국방 계약은 명시된 집계와 제한된 사례를 보여 주며 채택 데이터 전체는 원문 열람창에서 검색할 수 있습니다.
- 외부 원문 최신성, 실제 모집 여부, 교육 품질, 기업 동일성 전체, 공식 방산 지정은 이번 구현에서 새로 검증하지 않았습니다.

## 개발 환경과 재생성

Python 표준 라이브러리만 사용합니다. 프로젝트 가상환경은 상위 폴더 `.venv`에 생성되어 있습니다. 다른 PC에서는 Python 3.10 이상을 설치하고 아래 명령으로 환경을 새로 만드세요. 가상환경 폴더는 PC 간 복사하지 않습니다.

```powershell
# dashboard 폴더에서 실행
python -m venv .venv
.\.venv\Scripts\python.exe -X utf8 build.py
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

현재 작업 PC에서 `dashboard` 폴더를 기준으로 기존 가상환경을 쓰려면 위 명령의 실행 경로를 `..\.venv\Scripts\python.exe`로 바꾸면 됩니다. 로컬 서버를 실행한 경우 `http://127.0.0.1:8765`에서 확인하고 종료 시 Ctrl+C를 누릅니다.

브라우저 검증 스크립트 `tests/browser.cjs`와 `tests/visuals.cjs`는 Node.js와 Playwright, 설치된 Edge를 사용합니다. `NODE_PATH`를 Playwright가 들어 있는 패키지 경로로 설정한 뒤 각 스크립트를 `node`로 실행합니다. 이 도구들은 대시보드 열람이나 Python 빌드에 필요하지 않습니다.

## 파일 구성

- `src/index.html`, `src/style.css`, `src/app.js`: 화면·연결 규칙·검토 및 저장 기능
- `src/charts.js`, `src/views.js`: 외부 라이브러리 없는 SVG 차트와 단계별 화면
- `src/evidence.json`: 32개 검토 모듈의 데이터·목적·흐름·한계 정보
- `build.py`: 데이터 파싱·점검·압축 내장·독립 HTML 생성
- `data/raw/`: 첨부 CSV 54개 보존본
- `data/catalog.json`: 파일별 행 수·컬럼·결측·해시·채택 여부
- `data/audit.json`: 기업 연결 원장·급여 파생값·비용 및 일정 점검
- `dist/index.html`: 공유 가능한 최종 HTML
- `tests/`: 데이터와 실제 브라우저 검증
- `AGENTS.md`: 후속 작업의 기획·데이터 해석 규칙
- `TEST_REPORT.md`: 실행한 검증과 한계

데이터 채택은 `build.py`의 `SELECTED`, 추가 수집 제안은 `src/app.js`의 `MISSING`, 직무·교육 후보 규칙은 `ROLE_RULES`에서 검토할 수 있습니다. 수정 후 빌드를 다시 실행해야 HTML에 반영됩니다.
